## 1. 实验的三个层次

| 层次 | 保持相同的对象 | 主要目的 | 不能代替什么 |
|---|---|---|---|
| 状态重放 | 程序、状态、候选集合和数值输入 | 检验功能、隔离算法工作量与硬件执行 | 不能代替闭环搜索的端到端收益 |
| 固定预算闭环评估 | 程序集合、实例、随机命名空间、ACO 预算 | 研究整代时间、规模和资源使用 | 不等于两后端轨迹逐位相同 |
| 完整进化训练 | 外层规则、初始种群、schedule、搜索预算或墙钟预算 | 验证真实训练和最终规则质量 | 不能从一个组件微基准推导 |

同一后端的浮点路径变化可能改变后续搜索工作量。因此，所有关键性能结论尽量同时提供“相同状态的实现比较”与“完整闭环比较”。

## 2. 统一基线和消融

### 2.1 实现基线

| 标识 | 定义 | 比较角色 |
|---|---|---|
| CPU-Ref | 可验证的单树 FP32 标准实现 | 开发功能参考，不作为唯一速度对手 |
| CPU-Existing | 当前 Numba 路径的单树完整 FP32 版 | CPU 主速度基线 |
| CPU-Opt | M1 + M2 | 优化 CPU 方法 |
| GPU-Tensor | 合理批处理的 FP32 张量实现 | 通用张量化基线 |
| GPU-Existing | 当前 CUDA v2 的单树 FP32 版，无在线 FP64 审计 | GPU 主速度基线 |
| GPU-Opt | M1 + M3 | 优化 GPU 方法 |
| GPU-GP-Compose | EvoGP 等程序求值器与相同内层搜索的组合 | 外部组合基线；适配完成后纳入 |

CPU-Existing 和 GPU-Existing 均先移除信息素树独有工作、在线 FP64 重计分和旧回退逻辑。由这些移除带来的变化不算成新方法的加速。

外部框架无法原样支持 PDIV/逐节点裁剪时，先实现适配并记录成本；不偷偷减少保护行为。适配失败时记录具体限制，不提供不公平的速度数字。

### 2.2 分离软件优化与硬件收益

$$
S_{\mathrm{CPU}}=T_{\mathrm{CPU\text{-}Existing}}/T_{\mathrm{CPU\text{-}Opt}},
$$
$$
S_{\mathrm{GPU\ impl}}=T_{\mathrm{GPU\text{-}Existing}}/T_{\mathrm{GPU\text{-}Opt}},
$$
$$
S_{\mathrm{GPU/CPU}}=T_{\mathrm{CPU\text{-}Opt}}/T_{\mathrm{GPU\text{-}Opt}}.
$$

同时报告绝对秒数。不得将第一项和第三项的来源混合后仅展示最大倍数。

### 2.3 消融标识

| 标识 | 开关 | 用来验证 |
|---|---|---|
| A0 | 当前单树 FP32 路径 | 共同起点 |
| A1 | 动态排名等义重写 | 减少比较工作量 |
| A2 | 公共统计与作用范围外提 | 避免重复特征生成 |
| A3 | 特征—树联合代码生成 | 减少分派与中间物化 |
| A4 | ERC 结构代码缓存 | 编译摊销 |
| C1 | CPU 候选分块/原生求值 | 向量化与栈流量 |
| C2 | CPU 程序—实例二维调度 | 局部性和负载均衡 |
| G1 | GPU 程序资源分组 | 资源需求和尾部 |
| G2 | GPU 活跃状态分块 | 状态工作集与并发 |
| G3 | GPU 候选映射/融合选择 | 任务内与任务间资源权衡 |
| G4 | 有限执行计划选择器 | 未见负载上的配置选择 |
| X1 | CUDA Graph | 提交开销；与核心方法分开 |
| X2 | fast-math | 质量—速度扩展，非默认 FP32 路径 |

A1/A2 等通用变换同时提供给 CPU 与 GPU。执行两种消融：逐项加入解释累计收益；从完整系统逐项移除解释依赖。对 A3×G2、G1×G3、A4×编译新颖率等预定交互做小规模因子实验，不穷举所有开关。

## 3. 数据、程序 cohort 与随机流

### 3.1 数据划分

分离四类数据：编译器/执行计划 tuning、性能 holdout、算法训练/验证、最终质量测试。硬件选择器不能读取最终测试表现。

首轮默认采用二维 uniform Euclidean TSP。TSP100 和 TSP500 各自训练，实例数和使用规则如下。

| 集合 | 默认规模 | 使用方式 |
|---|---:|---|
| tuning | 每个 n 128 个独立实例 + 独立程序 cohort | kernel/计划选择器标定；支持B=128扩展 |
| 性能 holdout | 每个 n 128 个独立实例 | 固定工作量速度、E06/E08 |
| 每次 GP 训练 | G=50、每代 B=32，即默认 1600 个实例 | 预生成 schedule，实例不重复；方法间共享 |
| 验证 | 每个 n 128 个独立实例 | 选择最终候选和 pilot 策略；所有训练方法共享 |
| 最终测试 | 原始标准集：TSP100为1280个、TSP500为128个；每实例10次ACO重复 | 保留全部内容与顺序，不补样、不重划；候选和协议锁定后使用 |

P0 已检查现有数据：每规模建立32768个固定训练实例的池，原训练文件足够，无须补生成。标准测试集按用户指定完整保留，不以样本量偏小为理由改动。每个实例保留来源、行号、原始坐标、距离约定和哈希。

使用跨根种子的分离数据命名空间。配对的方法共享同一次训练 replicate 的初始种群与 schedule；不同 replicate 可以采用各自独立 schedule，但划分规则相同。

n=50/200/1000 为性能扩展或测试外推；不混入核心 n=100/500 的平均值掩盖差异。非 uniform 分布只在扩展实验中加入。

### 3.2 程序 cohort

冻结程序来自两种来源，避免只选择对新系统有利的树：

| 类型 | 组成 | 使用范围 |
|---|---|---|
| 真实 cohort | 独立 pilot 的第 1、25、50 代；分别来自 n=100 和 n=500 训练 | 主性能结果 |
| 人工诊断 cohort | 常数、统计终端密集、DistRank、TurnCos、深依赖/高活跃值等程序 | 机制和边界，不替代主结果 |

每个 cohort 保存所有程序及其常数位模式、节点数、深度、终端掩码、结构哈希和来源。tuning 与性能 holdout 按来源根种子分开，再检查重复结构比例；“未见结构”测试将相同结构簇整体隔离。

P 扩展使用预生成嵌套程序池。不能把少数程序复制很多份后将其称为真实大种群；复制型负载可单列研究代码复用与状态扩展。

### 3.3 状态快照

从不同构造阶段采样：早期、中期、接近完成，以及真实 fallback 事件。保存当前/前一城市、visited、候选顺序、信息素、任务迭代状态和程序。

快照生成与拷贝不进入正式速度计时。每个快照附完整尺寸和源任务 ID，禁止只保存“容易”的无 fallback 状态。

### 3.4 随机数协议

沿用或统一实现同一种计数器随机数，不因 CPU/GPU 改变发生器。逻辑坐标建议为：

```text
key: root_seed, phase, generation, instance_id, repeat_id
counter: aco_iteration, ant_id, construction_step, random_purpose, draw_index
```

程序间默认采用共同随机数，以利于配对评价；因此程序 ID 不进入该 key。若研究独立程序随机流，另立实验标识并纳入程序的逻辑 ID。两者不能在后端间混用。

随机用途隔离，例如初始城市、探索/利用分支和轮盘抽样分别占独立命名空间。坐标编码必须检查范围和溢出；统一整数到 FP32 uniform 的转换和区间端点。[R20]

随机流一致不保证浮点归约后的搜索轨迹一致。需要的是排除线程映射额外改变随机输入的因素。

### 3.5 去重与缓存

主性能实验关闭适应度结果去重，保留代码缓存；所有逻辑任务都执行，以便隔离执行器收益。

生产模式可以增加严格任务去重消融，但只允许完整程序语义、实例、初态、预算、随机流和数值合同一致的任务共享结果。结构相同、ERC 不同只能共享代码。

始终同时记录：请求任务数、实际执行任务数、结构数、精确程序数、代码缓存命中、结果缓存命中。分别报告实际执行吞吐和用户请求吞吐，不能混用。

## 4. 计时协议

### 4.1 计时边界

| 量 | 开始—结束 | 包含 | 单独说明 |
|---|---|---|---|
| T_setup | 读取本次工作负载—静态数据和运行环境可用 | 数据预处理、候选排序、必要 FP32 参考分母、上传和初始化 | 分开列分项；不为某后端隐去 |
| T_eval_cold | 首次提交原始 AST 和实例—本代适应度可用 | 必要分析、编译、计划、传输和搜索；计入相应 setup | 首次评价用户成本 |
| T_eval_warm | 静态数据及明确声明的代码缓存已就绪—本代适应度可用 | 仍需的任务准备、计划、状态初始化、搜索及归约 | 不能标成完整训练时间 |
| T_gen | 开始准备一代—本代规定工作完成 | 评价、外层操作及本代安排的验证/保存 | 有 checkpoint 的代单独标记 |
| T_train | 从本次训练输入加载—最终候选锁定并保存 | setup、所有代、编译、FP32 验证和正常保存 | 主端到端指标 |
| T_kernel | 设备上的指定 kernel/区间 | 设备执行 | 诊断指标；不代替 T_train |
| T_offline_score | 已返回的最终测试路径—统一长度统计完成 | 离线路径长度核算 | 不计入搜索/训练，不反馈搜索 |

预处理复用实验同时给出单次付费成本和复用次数，不只报告摊销后的平均值。编译缓存状态注明：冷、跨代已有缓存、同一批次完全预热。

### 4.2 异步计时

端到端采用单调墙钟。开始前清理上一次任务，结束时等待所有相关 stream 和 CPU 任务完成。设备区间用事件或合适工具记录。

异步阶段有重叠时，不直接将 H2D、kernel、D2H 分项相加充当总时间；同时报告实际关键路径和重叠区间。调度器的标定、试跑或计划搜索只要发生在运行时，都计入时间。

### 4.3 重复与机器控制

性能 pilot 每 cell 5 个配对 block；正式性能每 cell 默认 10 个配对 block。block 内随机化后端执行顺序，避免全部 CPU 后全部 GPU 的温度/系统状态偏差。

使用独占或可验证无争用的设备。记录 CPU 型号、物理核/SMT、内存和 NUMA、GPU 型号和实际架构、显存、驱动/编译器、功率限制、时钟政策、温度范围及进程占用。

记录异常运行并按预定义规则排除，例如出现其他 GPU 作业或硬件错误；保留排除原因和原始样本。不按“时间太慢”删除数据。GPU 降频若是所测实际运行的正常结果，应记录而非直接抹去。

profiling 与正式计时分开运行。工具重放、采样和额外计数器可能改变性能。[R16] [R17]

<a id="metrics"></a>
## 5. 观察指标及其含义

### 5.1 主结果指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 评价吞吐 | 实际完成的 `(program, instance, repeat)` / T_eval | 系统实际工作能力 |
| 每代时间 | T_gen；同时列 T_eval | 进化周期成本 |
| 完整训练时间 | T_train | 系统主目标 |
| 有效转移吞吐 | 合法的构造转移数 / 搜索时间 | 解释搜索吞吐；不含 padding |
| 完整 tour 吞吐 | 完成且有效的 tour 数 / 搜索时间 | 固定预算下的辅助指标 |
| 峰值内存 | CPU RSS、GPU 分配/保留/实际使用分别记 | 容量与工作集分析 |
| 编译比例 | 编译关键路径时间 / T_train | 专门化的实际代价 |
| 任务完成尾部 | 达到 90% 完成之后的剩余时间、任务耗时分布 | 负载不均衡；仅在可靠时间戳可用时 |
| 最终质量 | 离线核算的路径长度、可用时的参考 gap | 不与执行吞吐混为一谈 |

GPops/s 仅为辅助。消除工作可能降低已执行操作数但提高评价吞吐；不能以 padding、重复无用节点或无效候选充大吞吐。

### 5.2 算法级指标

每次详细诊断记录节点数/深度、活跃值估计、各终端和算子占比、精确程序/结构数量、真实候选数、fallback 次数与扫描候选量、排名比较量、静态和动态状态字节、预计算/物化字节、代码命中和失效次数。

fallback 必须同时报告“事件数占比”和“工作量/时间占比”。少量 fallback 也可能很贵，很多 fallback 也可能每次只剩很少候选。

源码插桩计数优先用于诊断运行；若在正式运行常开，先证明其开销并在全部后端一致处理。

### 5.3 GPU 诊断表

| 问题 | 指标/工具区段 | 一种可能解释 | 必须配合的验证 |
|---|---|---|---|
| 设备是否在等主机？ | 时间线、CUDA API、NVTX、kernel 间隙 | 编译/调度/同步开销 | 同负载减少提交后 T_eval 是否下降 |
| 活跃任务是否不足？ | grid、waves/SM、active/eligible warps、issue 活动 | 独立工作不足或资源限制 | 增加活跃任务与改变资源分配的对照 |
| 候选线程是否浪费？ | 线程/谓词有效比例、真实候选数 | visited 掩码或宽度不匹配 | 调整 lanes、压缩候选后有效工作吞吐 |
| 带宽还是延迟？ | DRAM/L2/L1 流量与吞吐、每请求事务、long scoreboard | 带宽、非合并读取或不足的并发访问 | 布局/复用干预，比较每有效评价字节量 |
| 是否 spill？ | registers/thread、local load/store、资源限制 | 活跃值或融合过多 | 分块/拆分后 local 流量和绝对时间 |
| 哪些指令昂贵？ | 源码/SASS、指令构成、特殊函数流水线 | log/tanh/div、整数索引、解释分派 | 同一状态的计算重写 |
| 同步或更新冲突？ | barrier 等待、原子请求、共享内存冲突 | ACS 时序、更新竞争 | 保持更新语义的局部合并/布局对照 |
| 工作负载长尾？ | 完成时间分布、最后一波运行 | 程序差异或任务切片不均 | 分组/调度实验，包含其额外开销 |

依据 Nsight Compute 的实际版本选择 `LaunchStats`、`Occupancy`、`SchedulerStats`、`MemoryWorkloadAnalysis`、`SourceCounters` 等可用区段。[R16] 名称不可用时查询替代项；指标缺失不填零。

高 GPU 利用率不等于高效率；低 DRAM 吞吐不排除访存延迟；occupancy 下降但耗时更短可以是正确优化。依据是绝对时间和有效工作量。[R16] [R18]

### 5.4 CPU 诊断表

| 指标 | 用途 | 注意事项 |
|---|---|---|
| CPU 时间、每核活动 | 并行度与负载 | 忙于 runtime 不等于做有效工作 |
| cycles、instructions、IPC | 指令效率 | IPC 高低不能脱离工作量解释 |
| 向量指令比例及实际宽度 | SIMD 是否生效 | 不只看“vectorized”标签 [R19] |
| 分支与分支失误 | 解释器分派/候选分支 | 与等义原生求值对照 |
| L1/LLC miss、内存带宽 | 缓存和访问瓶颈 | 同时看每评价字节量 |
| NUMA 本地/远程访问 | 多插槽局部性 | 固定绑定与首次触碰策略 |
| 工作区分配次数 | 分配与复用开销 | 不将缓存污染数据带入新任务 |

VTune 可用时优先使用其适配分析；也可用平台性能计数器和编译/汇编报告。只报告当前 CPU 真正支持的指标。[R19]

### 5.5 可选能耗

只在具有可靠测量条件时纳入。GPU 板卡能量和整机能量分开；CPU 包能量不包含全部内存/主机开销。不得用 GPU TDP 与 CPU 实测能耗比较，也不得将更短时间自动写成更节能。[R12]

## 6. 实验卡

<a id="e00"></a>
### E00 — 单树 FP32 合同与功能验证

**问题**：不同实现是否执行同一研究算法，是否存在任务漏算、缓存失效或更新错误？

**输入与对照**：CPU-Ref、CPU-Existing、GPU-Existing，再逐项加入新变换。覆盖全部 primitives、十终端、常数、单节点树、31 节点边界、距离平局、重复坐标、候选耗尽、m=1、首步 TurnCos、极端信息素和受保护除法。

**验证内容**：

| 类别 | 要求 |
|---|---|
| 离散结构 | 候选集合、DistRank 整数排名、visited、任务 ID 完全匹配 |
| 浮点局部值 | 与 FP32 标准路径比较；初始容差 `atol=1e-5, rtol=1e-4`，按节点类型记录最大误差 |
| 数值保护 | 不产生合同之外的 NaN/Inf，逐节点裁剪位置保留 |
| 随机流 | 重排任务、更改 tile/lane、换后端不改变约定的随机输入 |
| 缓存 | 修改任一依赖状态后正确失效；不同常数不误共享结果 |
| 搜索路径 | 每个最终 tour 恰好访问 n 个不同城市并正确闭合 |
| 固定更新 | 三种 ACO 分别测试，ACS 检查更新的读取/可见时点 |
| 工作完整性 | 每个逻辑任务执行规定次数，输出可对应原始任务 |

初始浮点容差不是对完整随机路径一致性的保证。超出容差时先定位函数、归约和选项，再在 pilot 阶段决定是否采用更准确实现；不能为正式结果逐例放宽容差。最终质量只在 E10 离线比较，不插入在线 FP64 修复。

**判读**：离散功能错误或非法 tour 表示实现失败，停止性能主张。仅浮点低位差异不等于算法错误，但必须进入 E10 检查其结果影响。

**产出**：合同 YAML、单元测试、跨后端差分测试、随机流/缓存失效测试和失败样例。

### E03 — 特征计算和动态排名重写

**问题**：M1 是否减少了相同状态上的必要工作，并带来整代收益？

**自变量**：原排名/掩码扫描；原统计组织/公共统计；分离特征数组/联合生成。程序分为不使用排名、只使用排名、统计密集、TurnCos 密集、真实混合。

**控制**：相同快照、FP32 距离和排序平局规则、原候选输出次序；之后使用相同预算闭环运行。

**规模**：n=50/100/200/500/1000；正常 K=20；诊断扩展 K=8/32/64。人工状态覆盖不同可行比例，但主闭环固定 K=20。

**记录**：排名比较数、扫描元素数、特征生成次数、中间写读字节、预排序时间/内存、局部时间及 T_eval。

**判读**：

| 结果 | 说明 |
|---|---|
| 排名工作量和时间下降，两端 T_eval 都改善 | 支持工作量重写；不是单纯 GPU 硬件收益 |
| 只有 n 较大/fallback 多时有效 | 支持分区应用，不能宣称普遍改善 |
| 局部变快但 T_eval 不变 | 热点占比低或被其他成本抵消；不作主加速贡献 |
| 预处理开销超过节省 | 对短生命周期不采用，报告摊销交叉点 |
| 不使用 DistRank 的程序仍明显变化 | 调查共享代码/资源变化，不能归因为排名减少 |

**退出条件**：E00 不通过即停止；若只在人工极端树有效，降为边界结果。

<a id="e04"></a>
### E04 — 解释器、树 JIT、联合 JIT 与编译摊销

**问题**：专门化什么时候值得？结构代码缓存是否改善真实训练？

**路径**：紧凑解释器、只编译树、联合特征—树编译、联合编译加 ERC 参数化缓存。

**自变量**：调用预算 I=50/100/500（同一 cell 的各后端相同）；程序节点数/活跃值；新结构占比；仅 ERC 变化占比；冷/跨代缓存/完全预热。

**数据**：真实 cohort 的自然新颖率作为主结果；人为设定的新颖率只用于解释交叉点。

**记录**：分析/编译/装载时间、代码字节、编译 cache 命中、寄存器/局部流量、执行时间、累计 T_eval/T_train。

**判读**：联合 JIT 的 warm 优势不足以支持 H5；必须在真实新程序序列中计入编译后仍有收益。ERC 参数化若减少编译但明显拖慢热执行，只在满足摊销条件的区间启用。

**关键对照**：所有后端获得同等的静态数据和精确代码复用机会；不让自己的系统热缓存而让外部框架每次冷编译。

**产出**：调用次数—累计时间交叉图、真实训练缓存曲线、解释/JIT 选择规则。

<a id="e05"></a>
### E05 — 优化 CPU 的独立价值

**问题**：M2 是否优于已有 Numba FP32 基线？

**自变量**：向量字节码/原生联合求值；候选块宽；实例优先/程序优先/二维调度；线程数 1、2、4、8…至全部物理核；SMT 为单列扩展。

**重点工作点**：B 小于、接近和大于物理核数；n=100/500；真实混合与资源差异显著的程序 cohort。

**记录**：T_eval、线程效率、SIMD 比例和宽度、标量特殊函数、工作区流量、LLC/内存、尾部和 NUMA（可用时）。

**判读**：

| 结果 | 说明 |
|---|---|
| 原生求值降低指令/栈流量且整代更快 | 支持编译求值机制 |
| 向量化率高但更慢 | 检查实际宽度、gather、数学函数和频率；不能据指标宣布优化 |
| 二维调度只在 B 小时有效 | 支持按并行度选择，不支持固定替换所有场景 |
| 线程数增加后吞吐饱和 | 用带宽/缓存/调度证据解释，不把更多线程默认当更强基线 |
| CPU-Opt 与 GPU-Opt 接近 | 确定硬件适用区间，不削弱 CPU 基线 |

**产出**：CPU 加速与扩展曲线、最优线程/分块策略、M2 的有效区间。

<a id="e06"></a>
### E06 — TSP500 规模退化的因果分析

**问题**：H4a—H4f 中哪些解释成立？

**设计 A：分开扩展轴。** 固定 n 扫描 P=25/100/400、B=8/32/128、R=1/4，每次只改变一个；固定外层预算扫描 n=50/100/200/500/1000。主锚点为 P=100、B=32、R=1、A=32、I=500、K=20。

**设计 B：保持任务数但改变任务组成。** 在可行点比较相同 PBR 的不同 P/B/R 组合，检查代码复用、静态数据复用和搜索状态的影响。此实验不改变单任务 A/I/K。

**设计 C：逐原因干预。** 进行等义排名重写、调整活跃任务量、改变 lanes/融合粒度、优化更新布局、冻结相同程序 cohort。只对具有前期证据的组合增加交互实验。

**记录**：CPU/GPU 各自 T_eval、阶段增长率、每有效评价字节、fallback 工作量、状态量、资源/尾部、所选配置。

**判读**：

| 观察与干预结果 | 支持的解释 | 不能外推 |
|---|---|---|
| 排名重写主要改善 n=500，且重复比较量同步下降 | 排名是规模差异的原因之一 | 排名是全部原因 |
| 分块后 L2/访问流量和 T_eval 改善 | 工作集/局部性有因果贡献 | 显存容量不足 |
| 降低寄存器/局部流量后并发与 T_eval 改善 | 资源限制有贡献 | occupancy 越高越好 |
| 更新阶段占比上升，优化更新后速度比恢复 | n² 更新成本有贡献 | 树执行已经最优 |
| 控制程序 cohort 后差异显著减小 | 训练程序分布有贡献 | n 本身没有影响 |
| GPU 绝对时间增长平缓，CPU 改善更多导致速度比变小 | 分母变化影响相对加速 | GPU 实现发生绝对退化 |
| 所有单项干预均无收益 | 当前假设不足或热点选择错误 | GPU 天生不适合 TSP500 |

**统计和范围**：超出容量时先使用已声明的分块执行；无法运行的实现记 OOM，不将其计算成无穷加速。不为某一后端单独减少 A、I 或 B。

**产出**：二维性能区间图、n 扩展分解、干预前后差分表、未解释部分。

### E07 — GPU 分组、状态分块与映射

**问题**：M3 中每个执行机制是否有独立价值？

**对照**：固定 GPU-Existing、不分组/按长度/按终端/按资源分组，分别加入活跃状态分块与候选 lanes 选择。

<a id="e08"></a>
### E08 — 执行计划选择器与留出验证

**问题**：自动选择是否比简单固定规则更好，收益是否大于选择成本？

**数据划分**：tuning 与留出按程序结构簇和实例分开；再设置一个未参与模型训练的 n。使用第二 GPU 时分别测试原模型直接迁移和少量重新标定。

**比较**：全局最佳固定、按 n 最佳固定、简单人工规则、选择器、有限集离线 oracle。固定计划只能在 tuning 数据上选择。离线标定的 CPU/GPU 计算时间和尝试配置数单独报告；在线额外编译、试跑和标定全部计入评价时间。不得给自适应方法无限调优而只给固定基线默认配置。

**记录**：预测误差、相对 oracle 的 regret、选择时间、运行时标定成本、失败/不可行预测、实际 T_eval。

**工程目标**：留出 median regret≤10%、p90≤25%；相对最佳固定计划的主集合几何平均速度提升至少 5%，且 95% CI 下界大于 1。目标是保留方法的标准，不是先验结果。

**判读**：

| 结果 | 说明 |
|---|---|
| 预测误差较大但选择 regret 小、端到端快 | 选择任务有效，不要求精确预测每个秒数 |
| 预测准确但比固定策略慢 | 选择/标定成本抵消收益，不保留复杂选择器 |
| 只在训练结构上有效 | 过拟合，不能声称未见程序适用 |
| 原模型迁移失败，重新标定有效 | 支持可重新调优，不支持零样本硬件迁移 |
| 最佳固定计划已接近 oracle | 无需复杂自适应；保留简单策略与区间分析 |

**产出**：留出数据、模型、选择开销、regret 分布和最终保留策略。

<a id="e09"></a>
### E09 — 固定工作量的完整训练

**问题**：局部收益能否进入包含新程序和验证成本的真实 GP 训练？

**主设置**：AS，n=100/500 分开；P=100、B=32、R=1、A=32、I=500、K=20、G=50。比较 CPU-Opt、GPU-Existing、GPU-Opt；CPU-Existing/GPU-Tensor 的完整训练视 pilot 可行性预先决定，不能在结果出来后因其表现好而删除。

**重复**：pilot 3 个独立 GP 根种子；确认性默认 10 个，按用户本轮要求执行。正式数量如需调整，应依据pilot方差在冻结前统一修订；不得通过“跑到显著”为止决定停止。

**控制**：初始种群、遗传算子、schedule、FP32 验证政策、checkpoint 频率和选择准则。不同后端数值差异可能使后续种群不同，同时使用 E01 冻结种群结果解释纯执行差距。

**记录**：T_train、逐代 T_eval、编译/新结构率、程序特征变化、验证耗时、完成评价数、最终候选来源。主表包括 cold setup；附表提供剔除共享一次性 setup 的结果。

**判读**：完整训练有收益才支持端到端训练加速；只有冻结种群有效说明编译或外层开销仍是问题。训练曲线分叉不自动等于某后端数值错误，应结合 E00/E10 判断。

**产出**：完整训练时间表、逐代成本曲线、编译占比及最终候选清单。

<a id="e10"></a>
### E10 — FP32 后端的最终路径质量

**问题**：取消在线 FP64 重算后，不同实现是否产生不可接受的最终质量差异？

**两个层次**：同一冻结程序在不同求解后端上测试，隔离执行差异；各后端独立训练得到的最终候选在同一独立测试集上测试，检验完整训练结果。

**主数据**：原始标准测试集，TSP100为1280个、TSP500为128个；每实例10个随机重复。候选和测试协议先锁定，再读测试结果。不得增补测试实例或改变原顺序。

**预设对比**：固定程序层比较 GPU-Opt 与 GPU-Existing、CPU-Opt 与 CPU-Existing，以及 GPU-Opt 与 CPU-Opt；完整训练层比较 GPU-Opt 与 CPU-Opt、GPU-Opt 与 GPU-Existing。两层分别形成主要检验族，并在核心 n=100/500 范围内控制多重比较；扩展规模和尾部指标单列。对比方向始终为“新方法减参考方法”，长度/gap 越小越好。

**离线核算**：保存最终 tour，按统一距离约定核算长度；可使用离线高精度累加。只核算路径，不重新运行 FP64 ACO。该成本单列，不进入搜索时间，不用于训练选择或回退。

**指标**：路径有效率；每实例平均长度；有可靠每实例参考值时计算 gap；配对差异、分位数、最差十分位结果和置信区间。

**主非劣界**：若使用每实例参考 gap，定义 `Δgap = gap_new - gap_reference`，以百分点计，预设容忍界 +0.10 个百分点。单侧 95% 上界≤+0.10 才支持所测范围的非劣。只有相对路径长度可用时，改用 `100*(L_new-L_reference)/L_reference`，阈值 0.10%，并明确不是“最优 gap”。正式协议只选一种主尺度，不事后挑有利者。

**判读**：上界超过容忍界可能是退化，也可能证据不足；区分均值方向与区间宽度。`p>0.05` 不等于相等。即便平均非劣，也单列尾部异常和失败率。

**后续动作**：出现实质退化时检查浮点数学选项、概率归约、候选顺序和 ACS 更新；修复后使用新版本重新验证。不得恢复在线 FP64 重求解来掩盖。

<a id="e11"></a>
### E11 — 等墙钟预算与预算投向

**问题**：更多评价吞吐能否改善自动算法设计，预算应该投在哪里？

**设计分两步**：先在相同搜索政策下比较 CPU-Opt/GPU-Existing/GPU-Opt 的质量—时间曲线；再在 GPU-Opt 上比较四种预算投向，并用 CPU-Opt 作为对照验证趋势。

| 策略 | 默认设置 | 变化 |
|---|---|---|
| S0 更多代数 | P=100、B=32、R=1 | 在时间上限内执行更多完整代 |
| S1 更广种群 | P=400、B=32、R=1 | 增加候选广度，精英比例固定 10% |
| S2 更多实例 | P=100、B=128、R=1 | 提高评价覆盖；训练 schedule 同规则扩展 |
| S3 更多重复 | P=100、B=32、R=4 | 降低随机评价噪声，增加单代成本 |

A/I/K、语言和搜索规则不变。不能把增加蚂蚁数量等算法变化混入本实验。

等时间实验不受固定 G=50 的 1600 实例上限限制。按 `(root_seed, n, generation, instance_slot)` 定义可扩展、无测试泄漏的训练实例流，足量预生成或用确定性生成器提供；实例生成、预处理和传输的实际成本按统一边界计入。比较组共享相同逻辑实例流，不因某后端更快就改用更容易的样本。

**预算设定**：用独立 pilot 得到每规模的参考时长 T_ref，正式分析预算为 0.25/1/4×T_ref，各比较方法在同一规模使用相同秒数。T_ref 和具体秒数在正式实验前登记，不根据测试质量调整。

**计算控制**：pilot 比较全部策略；正式预算投向最多保留两个预先选定策略，选择依据仅为 pilot 验证，不使用最终测试。正式根种子默认10。可从最长预算运行的预定检查点生成 anytime 曲线，前提是执行/选择政策不依赖未来更长预算；否则分别运行。

**截止规则**：截止时只允许使用已完整评价并完成规定候选选择的代；未完成代不参与选择。记录未完成工作和清理时间；不能把截止后的计算结果回填。验证/候选选择消耗预算，离线测试计分不消耗训练预算。

**指标**：最终锁定程序的测试长度/gap、质量—时间曲线、达到预设验证质量的时间、完成代数和任务数、程序多样性、评价噪声、总训练实例数。

**判读**：

| 结果 | 说明 |
|---|---|
| 同政策 GPU 在同时间得到更好规则 | 支持执行加速转化为 AAD 收益 |
| S2/S3 优于 S1 | 支持本设定下优先增加评价覆盖/重复的预算策略；只有噪声和排序稳定性等诊断一致时，才进一步归因为评价可靠性 |
| 吞吐更高但测试质量不变 | 只支持已验证的效率贡献；可能存在搜索/表示限制、收益饱和或统计不确定，不能直接断言原因 |
| 验证更好、独立测试更差 | 可能过拟合或选择噪声，不支持泛化改善 |
| 只有一种 n 有质量收益 | 结论按规模限定 |

<a id="e12"></a>
### E12 — ACO 变体与硬件迁移

**问题**：方法在不同状态依赖和硬件上是否仍有效？

**变体**：AS、同步 ACS、MMAS 的 E00 和主要性能点都必须完成。完整训练主实验以 AS 为入口；在下一依赖强度上优先补充同步 ACS，而不是只挑最快变体。

**硬件**：主 GPU 使用实际可获得设备并记录清单；至少一个不同架构/资源比例的 GPU作为迁移目标。若只有一张设备，仍可完成核心研究，但不声称跨架构验证。CPU 同样记录实际核数和指令集，不以产品名推测 SIMD 支持。

**记录**：绝对时间、三个速度比、所选配置、资源指标、重新标定成本、质量抽查及失败配置。

**判读**：AS 成功、ACS 无效说明更新依赖限制优化范围；原配置失败而重新标定成功说明方法可调优而非参数通用。多 GPU 只在单卡稳定后另作吞吐扩展，不能掩盖单卡机制。

<a id="e13"></a>
### E13 — AAD 适用范围扩展

**问题**：复用的是核心执行方法，还是仅仅代码风格？

**层 A，核心可做**：保留 GP-ACO 宿主，换外层候选生成政策，例如随机程序搜索或另一种进化选择。证明接口不绑定某个外层算法，不宣称跨内层任务。

**层 B，条件扩展**：选择 GP 调度规则设计作为不同宿主，新增特征/状态适配器，复用 IR、CPU 编译、任务描述和可用的 GPU 计划组件。先补齐其直接相关工作，包括技术表 R13。

**记录**：复用模块、新增特征和同步规则、适配代码与实现工作清单、同语义功能测试、强 CPU/GPU 基线和端到端时间。

**判读**：主要组件不改即可获得收益，支持在所测第二任务上的迁移；需要重写所有 kernel 和计划逻辑，只支持设计思路可借鉴；只完成层 A，不扩大论文标题为通用 AAD 平台。

<a id="statistics"></a>
## 7. 样本量、统计与结论标准

### 7.1 性能

每 cell 用配对运行 block。报告中位绝对时间、离散程度、配对速度比和置信区间。跨 cell 汇总使用预先固定分层权重的几何平均；同时展示所有主要 cell，避免便宜工作负载数量更多而支配平均值。

预设工程保留标准：主集合几何平均提升≥5%，配对 95% CI 下界>1；单个核心 cell 退化>10% 时必须列出并提供配置回退或限定范围。小于 5% 但稳定的改善可以报告，不自动升格为主要贡献。

分层权重默认对 n=100/500、三种变体、early/mid/late 等权。无法运行的 cell 单独呈现，不能从汇总中无声删除。跨硬件不混合为单个速度比。

### 7.2 质量与完整训练

默认10个独立GP根种子为确认性计划量，pilot 3个不作为最终结论。利用pilot方差在冻结前做样本量/可检测效应评估；资源不足时先减少非核心配置，不通过事后改变显著性门槛补救。

测试实例对所有候选共享，因此 champion 与实例是交叉结构，不应把所有 `champion×instance×seed` 当作独立样本。先在实例内聚合 ACO 重复，再对 GP 根种子和实例做配对的交叉/多层重采样；方法比较保持相同索引和配对关系。

最终报告效应量和区间。主要质量对比按 E10 定义检验族，对单侧非劣检验使用 Holm 校正；同时报告未经校正的效应区间，并明确族级结论以校正检验为准。单个对比的单侧 95% 上界规则不自动控制整个检验族的错误率。E11 在冻结时单列政策比较族。探索性后验分析标注探索性，不与主假设混用。

不能用“未显著”证明相等。非劣与等价不同：非劣检查一个预设上界；声称等价需要两侧界均成立。

### 7.3 机制支持的最低条件

机制结论至少具备：功能合同通过；在受控输入下干预改变目标工作量或资源行为；绝对时间出现对应变化；在真实负载中说明效果占比；排除关键替代解释。

计数器相关性只能提出假设。一次优化同时改变布局、编译和线程数时，不能仅凭一个计数器变化将全部收益归给它。

## 8. 全局结果判读表

| 实验结果 | 支持什么 | 不支持什么 | 研究动作 |
|---|---|---|---|
| CPU/GPU 都因排名重写变快 | 通用工作量优化有效 | GPU 独有创新 | 将共享收益单列，继续验证硬件部分 |
| GPU 微基准快，T_train 不变 | 组件优化 | 端到端训练加速 | 检查编译、验证和主机关键路径 |
| GPU-Opt 快于旧 GPU，接近 CPU-Opt | GPU 实现有所改善，CPU 也强 | GPU 在所有大规模任务必胜 | 报告适用边界 |
| 只在完全热编译时快 | 复用场景收益 | 新程序密集训练收益 | 使用解释器/缓存选择并说明寿命边界 |
| TSP500 改善来自固定计算重写 | 该路径是原因之一 | 所有大 n 都是相同瓶颈 | 验证其他 n/程序/变体 |
| 更高 occupancy 却更慢 | 原指标不是正确目标 | 已经更接近硬件极限 | 回到绝对时间和有效工作 |
| 分桶更快且减少 spill/尾部，开销已计入 | 资源分组机制 | 任意分桶都有效 | 在留出程序验证 |
| 选择器不如按 n 固定策略 | 简单策略足够 | 复杂自适应贡献 | 移除或缩减选择器 |
| FP32 平均非劣但尾部更差 | 平均指标上的非劣 | 无风险的完全等价 | 单列尾部与异常实例 |
| 速度更快，等时间质量也更好 | 执行和 AAD 价值双重证据 | 对所有设计方法泛化 | 限定所测范围 |
| 速度更快，等时间质量无改善 | 系统效率贡献 | 学习质量提升 | 分析预算投向与表示限制 |
| 更换外层算法有效 | 评估器接口解耦 | 跨问题/跨宿主泛化 | 需要 E13 层 B |
| 历史差异无法复现 | 原版本/边界尚不清楚 | 新方法解决了已知退化 | 诚实记录并以新现象重设问题 |

## 11. 执行优先级与停止规则

### 11.1 核心序列

`E00 → E01/E02 → E03/E04 → E05/E07 → E06/E08 → E09/E10 → E11 → E12/E13`。

E12 的三变体功能检查提前并入 E00；第二硬件和第二任务后置。E06 贯穿优化过程，不等所有优化结束后才调查 TSP500。

### 11.2 必须保留的实验

强 CPU/GPU 基线、单树 FP32 功能、n=100/500、真实 cohort、计入编译的时间、至少一组完整训练、最终路径离线质量和回归点。

资源不足时优先缩减人工极端点、完整因素组合、更多 ACO 变体的完整训练和第二任务，不删除强基线或只保留最好规模。所有删减发生在正式结果查看前并更新协议版本。

### 11.3 方法退出规则

局部复杂优化连续两个独立留出 cohort 无净收益且未显示明确适用区间时，停止扩大实现，保留实验记录。编译器或选择器只有微基准收益时，降级为可选组件。功能失败的结果不能作为速度胜出。

“没有证实某条假设”是该实验的有效结论，不要求每个模块都成为论文贡献。
