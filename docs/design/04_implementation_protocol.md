# 执行协议 v1.1：数据冻结与第一阶段实现

日期：2026-10-10。范围：P0 数值/数据规范与 P1 强基线、先导训练。本文是对 2026-10-02 研究计划的执行补充，不把计划目标写成已有结果。

## 1. 本轮冻结决策

| 项目 | 执行值与理由 |
|---|---|
| 工作目录 | 所有代码、环境、缓存、快照及结果均在当前项目内 |
| 模型 | 单棵转移树；固定 AS、同步 ACS、MMAS；主训练先用 AS |
| 科学规模 | P=100，B=32，R=1，A=32，I=500，K=20，G=50 |
| 树与进化 | 节点数≤31、深度≤5；初始深度2–4；交叉/变异/复制0.80/0.15/0.05；精英10%；锦标赛4 |
| 初始零规则 | 10% ZERO，其余随机生成；所有个体实际执行，不用零规则缓存跳过任务 |
| 变异 | 子树/节点/ERC 比例0.5/0.3/0.2；ERC 高斯扰动标准差0.1并裁剪到[-1,1] |
| 数值 | 在线搜索、路径长度和适应度均为 FP32；关闭 fast-math 和 FMA 收缩；不在线 FP64 重算 |
| 局部搜索 | 关闭，避免混入其他工作负载 |
| 独立训练次数 | pilot 3 个根种子1001–1003；正式默认10个2001–2010；取代旧稿5/20的预设量 |
| 性能重复 | pilot 每 cell 5 个配对 block；正式10个；功能 smoke 的一次测量不冒充性能实验 |
| 主硬件 | RTX A5000；多卡分配独立运行，不宣称单次训练的多卡加速 |

上述参数为研究控制变量，不是已经证明最优的设置。优化阶段必须保持共同算法语义。每个版本记录差异与失效范围。

## 2. 数据与泄漏控制

| 集合 | TSP100 | TSP500 | 使用方式 |
|---|---:|---:|---|
| 可选原始训练数据 | 1,280,000 | 64,000 | 带用户提供的最优标签路径 |
| 本轮固定训练池 | 32,768 | 32,768 | 每次50代运行无重复抽取1600个；不同根种子允许重叠 |
| 验证 | 128 | 128 | 每5代选最终候选；固定3个ACO随机重复 |
| kernel tuning | 128 | 128 | 调参；支持后续B=128扩展 |
| 性能 holdout | 128 | 128 | 不用于执行计划调参 |
| 原始标准测试 | **1,280** | **128** | 保留全部实例、标签和原顺序；不扩充、不重划 |

训练/验证/tuning/holdout 从原训练文件选取。坐标原始 FP64 字节的 SHA256 标识实例。划分时排除现有对应规模测试文件的哈希，检查集合内唯一性和集合间无交集。运行时随机 key 使用实例哈希的前64位，另查所用批次没有 key 碰撞。源文件的 SHA256、行号和派生数组记录在 `Datasets/splits/` 和 `Datasets/processed/v1/`。

`.npy` 使用不压缩存储，支持 mmap；只保存所选行，避免每代解析巨型文本。同时保留原始坐标和原标签路径，便于以后离线核算。标签身份记录为 `user_supplied_optimal_tour`；路径合法性和文件完整性已经检查，但尚未为每个标签重新生成求解器最优性证书。

最终测试只评估每次训练由验证选出的一个冠军，使用10个ACO随机重复。测试实例不是128次独立训练；统计时必须区分实例、ACO重复和独立GP根种子。

## 3. 类型、形状和计算

DEAP 类型为 `TrField`。这是同一候选边数值场类型；当前单树系统没有额外的布尔、路径或信息素树输出类型。标量终端的广播由后端实现。因此这是使用 Typed API 的**单一数值类型语言**，不能声称类型系统区分了全部运行时形状。

设任务数为 $E=PBR$，每任务有 $A$ 只蚂蚁。当前城市为 $i$，前一城市为 $h$，可行候选集合为 $C$，其大小为 $m$。候选集合不规则，逻辑形状写为 `[E,A,m]`；实现中用候选表和 visited 掩码表示，不把所有动态终端保存为整代巨型张量。

令 $d_{ij}$ 为 FP32 连续欧氏距离，$\eta_{ij}=1/\max(d_{ij},\epsilon)$，$b_j=\tau_{ij}\eta_{ij}^2$，$q_j=b_j/\sum_{k\in C}b_k$。基准总权重过小时，特征中的 $q$ 按均匀分布计算。$\epsilon=10^{-12}$。令

$$S(x_j)=\tanh\!\left(\frac{x_j-\bar x}{\sigma_x+10^{-8}}\right).$$

标准差使用总体方差。实现先减去第一个可行值，再计算均值和两遍中心化方差，保证常数向量输出恰为零。

| Terminal | Type | 实際输入 | 定义 | 逻辑 shape / 范围 |
|---|---|---|---|---|
| RTau | TrField | 当前行信息素、可行集合 | $S(\log\max(\tau_{ij},\epsilon))$ | `[E,A,m]`，[-1,1] |
| REta | TrField | 当前行启发值、可行集合 | $S(\log\max(\eta_{ij},\epsilon))$ | `[E,A,m]`，[-1,1] |
| BaseConf | TrField | 基准权重及集合大小 | $\tanh(\log\max(q_j,\epsilon)+\log m)$ | `[E,A,m]`，[-1,1] |
| DistRank | TrField | 距离、可行掩码、候选顺序 | $1-2r_j/(m-1)$；零起始排名；m=1时0 | `[E,A,m]`，[-1,1] |
| Entropy | TrField | 可行集合上的基准概率 | $2[-\sum q_j\log\max(q_j,\epsilon)]/\log m-1$；m=1时-1 | `[E,A,1]` 广播，[-1,1]附近 |
| ConstructProg | TrField | 构造步 $s\in[1,n-1]$、城市数 | $2s/(n-1)-1$ | `[E,A,1]` 广播，[-1,1] |
| ACOProg | TrField | 迭代 $t\in[1,I]$、总预算 | $2(t-1)/\max(I-1,1)-1$ | `[E,1,1]` 广播 |
| Stagnation | TrField | 全局最好解未改善迭代数 $u$ | $2\min(u/I,1)-1$ | `[E,1,1]` 广播 |
| MutualRank | TrField | 完整静态双向近邻排名 | $1-[(r_{ij}-1)+(r_{ji}-1)]/[2\max(n-2,1)]$，裁剪[0,1] | `[E,A,m]`；此处排名从1起 |
| TurnCos | TrField | 前一/当前/候选城市坐标 | $(x_i-x_h)\cdot(x_j-x_i)/(\lVert x_i-x_h\rVert\lVert x_j-x_i\rVert+\epsilon)$ | `[E,A,m]`，裁剪[-1,1]；无前驱时0 |
| 常数/ERC | TrField | 无搜索状态输入 | 命名常数-1、-0.5、0、0.5、1；ERC初始化均匀[-1,1] | 可广播标量 |

距离平局按城市编号排序。正常候选表中的 DistRank 是**过滤 visited 后**的动态排名，不是原始表位置。候选表耗尽时从所有未访问城市计算排名，并按规定执行第一最大分数选择；不是在全部城市上继续轮盘抽样。

| Function | 输入 Type | 输出 Type | 未保护的结果 |
|---|---|---|---|
| ADD | TrField × TrField | TrField | $a+b$ |
| SUB | TrField × TrField | TrField | $a-b$ |
| MUL | TrField × TrField | TrField | $ab$ |
| PDIV | TrField × TrField | TrField | $ab/(b^2+10^{-6})$ |
| MIN | TrField × TrField | TrField | $\min(a,b)$ |
| MAX | TrField × TrField | TrField | $\max(a,b)$ |
| ABS | TrField | TrField | $|a|$ |
| NEG | TrField | TrField | $-a$ |

每个函数结果单独保护：NaN→0，正/负无穷→±10，并裁剪到[-10,10]。MIN/MAX 的 NaN 先传播到算子输出，再保护。禁止把逐节点裁剪移到树末尾。所有二元算子支持广播；输出对应候选边场。DEAP 仅管理树结构和遗传操作，实际求值使用 postfix 解释器或 CUDA 生成代码，不调用占位 Python primitive 计算结果。

GP 树输出 $z_j$，状态转移权重为

$$w_j=b_j\,[1+\tfrac13\tanh(z_j)].$$

这个有界乘法修正是冻结的工作负载定义，并非本轮加速贡献。其乘子位于[2/3,4/3]内。AS/MMAS使用轮盘选择；同步ACS按$q_0=0.9$混合贪心和轮盘。轮盘比较使用累计值大于等于阈值；贪心平局选第一个候选。

## 4. 固定宿主和随机协议

AS：$\rho=0.5$，所有蚂蚁按编号递增累加 $1/L_a$，再进行对称蒸发与更新。GPU 不用浮点原子无序相加。

同步ACS：$\rho=0.1$，$\xi=0.1$；每一步先完成全部蚂蚁的选边，然后按无向边使用次数施加等价局部更新，再进入下一步。闭合边也更新。全局更新仅作用于全局最好路径。这不是逐蚂蚁顺序执行的异步ACS。

MMAS：$\rho=0.02$，$p_{best}=0.05$；每25迭代强化restart-best，否则强化iteration-best。改善时更新上下界；每100迭代检查分支因子，满足停滞条件时重启。精确定义见 `SearchConfig` 和 CPU/CUDA 固定更新；这些是锁定历史实现的特定变体，不宣称与任意 ACOTSP 命令行默认值一致。

Philox4x32-10 用于CPU/GPU。根种子、训练/验证阶段、代数和重复通过命名空间派生64位 key，再与实例 key 异或。counter为迭代、蚂蚁、构造步、随机用途四个32位整数。用途区分最近邻初始化、起点、ACS分支、轮盘。取输出高24位映射到[0,1)。程序之间使用共同随机数，不把程序物理编号写入 key。重新分波次或调换程序次序不应改变随机输入；浮点归约顺序仍可能导致不同的闭环轨迹。

## 5. 适应度、选择与缓存

$$\operatorname{gap}(L,L^*)=100(L-L^*)/L^*,\qquad
f(p)=\frac1{BR}\sum_{b,r}\operatorname{gap}(L_{pbr},L_b^*).$$

分母是标签路径在同一FP32几何下的长度，**不是baseline ACO长度**。训练记录本代最优、种群中位数、固定ACO均值及差值（百分点，负值更好）。验证记录验证选出冠军的均值，与相同实例/随机流的ACO对照。最终模型为历次规定验证中选出的冠军，不是盲目使用最后一代训练最好个体，也不是测试表现最好个体。

固定ACO使用ZERO规则，缓存键包含源码哈希、实例标识、搜索设置及随机种子。共享规范参考采用固定 GPU-Existing、lanes=8、active=3200、generated=true；CPU/GPU训练不能各自产生不同分母或基准。CPU训练需要已有缓存或可用GPU生成该对照。当前pilot按需填充缓存并单独记录代价；正式性能比较前应提前填充，两边共享缓存条件。适应度结果缓存关闭，代码缓存开启。

验证每5代发生一次：当代训练前5名加历史冠军，共最多6个候选；固定128实例、3次ACO重复；均值最小者胜出，平局按节点数及语义哈希决定。重复程序仍实际执行。保存完整种群的语义哈希、忽略ERC数值的结构哈希、依赖掩码与字节码，供后续非挑选性重放。

## 6. 实现边界与基线修正

CPU保留历史实现的按实例并行、紧凑候选、标量广播、Numba向量列解释。GPU保留program×instance展平、每任务一个block、蚂蚁×候选子warp、生成代码/字节码两条路径。主配置每蚂蚁8线程，共256线程/block。显存保存每任务信息素与蚂蚁状态；实例几何共享。显存不足时分波次，不减少逻辑任务。

移植时统一的修正包括：CPU/GPU随机数映射原本不同；方差的消减误差；FP32常量与中间量；AS浮点累加顺序；MIN/MAX非有限值语义。另移除旧信息素树、局部搜索和在线FP64重算。**这些都属于建立共同基线，不计为M1/M2/M3的新增加速。** 早期smoke与后续提交版按源码哈希区分，不能跨版本拼成配对加速比。

解释和生成代码不是共享fitness。`structural_hash` 只表示忽略ERC数值后的结构相同，当前尚未实现常数参数化代码缓存。CPU-Opt、GPU-Tensor、GPU-GP-Compose和GPU-Opt尚未完成。已安装PyTorch不等于已完成张量对照。

## 7. 计时与证据边界

`eval_wall_s` 从接收已准备几何/程序开始，计入本次编译、初始化、上传、搜索、回传；数据读取和几何构建单列，外层适应度、选择、验证与保存进入整代/训练墙钟。设备事件搜索时间不包含所有这些步骤。CUDA pool reserved bytes 不是显存峰值采样；编译资源来自kernel attributes，不冒充硬件计数器。

`--profile-stages` 对construct/update单独插桩，只用于诊断。当前集群GPU性能计数器受管理员权限限制；先使用事件、时间线和编译资源，未采到的指标标为缺失。运行中若检测到其他GPU进程，将该运行标为争用；先导质量记录可保留，但不能作为干净正式速度样本。

checkpoint用原子替换提交。源码或参数不一致拒绝恢复。恢复运行不作为连续完整训练速度样本；其累计时间不包含进程停止期间。外层日志写入仍存在毫秒级边界差别，正式结论以完整run计时及明确定义的原始记录为准。
