## 2. 预生成输入与计时边界

每run由该卡先生成53个ACO参考场景：50个训练批次和3个验证随机重复。保存完整FP32几何、候选表、近邻排名、初始化、ZERO路径和长度、日程以及初始种群。每文件SHA256登记，READY提交后消费者只读。输入库不复用其他源码版本的缓存，也不在GP训练期间补算参考。

输入预生成计时独立记录几何、初始化、ZERO搜索、存储及整体墙钟。GP训练使用同一日程和冻结输入，从输入加载至冠军和checkpoint写入的时间为`training_wall_s`。同时记录`training_plus_input_preparation_s`，不隐去一次性准备成本。E00设备资格检查耗时另列，不归为搜索算法耗时。

每attempt使用独立CuPy/driver缓存目录。资格检查及ZERO参考可能预热公共内核，100程序的GP训练不做额外全种群预热。此条件称为“预生成输入和参考下的连续训练”，不把它写成完全冷系统启动。编译调用成本及每代代码命中仍逐代记录。后续比较必须匹配此缓存政策，并单列预生成输入的共享一次性成本。

输入库预计为数十GiB，主要是TSP500的距离／启发／排名数组；换取跨方法可核验的输入一致性。不得因占用空间擅自删除基线或现有实验产物。

## 4. 修复共享文件系统状态竞争

旧诊断控制器可能在本机未见COMPLETE、而远端进程已经退出时立即写FAILED。NFS文件可见性延迟与这一检查顺序相符。当前4个案例的原始输出、完成标记、路径一致性和内容哈希均已核验；它们不是计算失败。

新控制器直接读取结束标记；检测进程退出后到worker所在主机复查。无远程证据时至少等待180秒且多次核查，未知SSH状态不释放租约。完成标记晚到后，即使之前已有控制器失联报告，也允许通过内容校验纠正队列。真正worker异常与COMPLETE冲突保留失败并请求复核，不自动覆盖。

历史FAILED、worker日志及结果不删除。纠正写入`STATE_RECONCILED.json`，包含原记录哈希和“未重复科学计算”的说明。升级只替换控制器源码；旧两个队列的campaign、worker commit和科学预算保持不变，控制器升级另存审计。

## 5. 运行与优先级

```bash
source scripts/env.sh
python scripts/research_pool.py             # 只读查看20训练+18映射block
python scripts/research_pool.py --execute   # 首次启动；须先提交源码
```

控制器及worker均nohup，60秒扫描空闲A5000；UUID锁和启动复查与旧队列共用。不抢占其他用户。旧队列已出现就绪任务时先让它获取设备；新队列内部优先派发正式训练，再运行映射block。后期cohort缺失时仅等待该项，其他独立任务仍可运行。

20次正式训练及18个映射block是有限清单，不能为填满设备无限增加重复。CPU完整基线按独立CPU协议准备，本次不自动安排NeSI或与GPU任务争用主机做CPU计时。
