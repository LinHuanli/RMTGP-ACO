# 实验产物、结果分层与溯源规范

本规范解决目录和证据管理问题，不改变搜索预算、实验假设或统计单位。当前产物登记表是 `configs/experiments/registry.yaml`。所有路径均在本项目内。

## 1. 先区分证据等级，再区分实验

| 等级 | 允许用途 | 不允许的解释 |
|---|---|---|
| `formal` 正式确认性实验 | 预先冻结协议、完成预设重复、通过审计后的论文主结论 | 不能把先导结果改名后升级为正式结果 |
| `pilot` 先导实验 | 估计成本、检查效应量、确定后续实验；可以使用完整科学预算 | 3个GP根种子或5个性能block不自动成为正式实验 |
| `diagnostic` 独立诊断 | 阶段插桩、工作量计数、快照、profiling | 插桩时间不能混入无插桩加速比 |
| `smoke` 功能与流程验证 | 小预算检查，或单次完整预算流程检查 | 不能用于性能统计、训练质量结论或补足重复次数 |
| `historical` 其他研究的历史资料 | 来源核查、协议差异和历史现象复核 | 不能直接与本轮结果配对 |

执行状态与证据等级是两个字段。`completed`只说明一次运行结束，不表示其成为正式结果。`failed`、`timeout`、`contended`、`partial`必须保留；不能删除失败后只留下成功目录。

**当前没有已完成的正式确认性实验。** 原 `a5000-main-v1` 的“main”只是调度队列名称。它的5-block测量仍是先导。原 `pilot-v1` 的50代训练使用3个GP根种子，仍是先导。

## 2. 目录结构

```text
artifacts/
  README.md                       自动生成的产物索引
  runs/
    formal/E01/p01/<run-id>/       正式运行；当前尚未启用
    pilot/E01/p01/<run-id>/        原始先导记录
    diagnostic/E01/p01/<run-id>/   独立插桩与profiler记录
    smoke/E00/p01/<run-id>/        功能验证；不进入科研统计
  inputs/<input-set>/p01/          只读冻结输入、manifest与校验值
  cache/aco-baselines/             可复算的共享ACO缓存
  provenance/
    source-snapshots/managed/<commit>/ 新任务的不可变源码
    source-snapshots/legacy/       待旧任务结束后迁入的原快照
    historical/E02/p01/            历史导出副本和实际文件SHA
    bootstrap/p01/                 整理前的环境、仓库和开发检查原始包
  operations/                     锁、启动器、调度和目录迁移审计

docs/results/
  README.md                       唯一的结果导航入口
  formal/                         仅正式结果；没有结果时明确写未开始
  pilot/E01/p01/                   已有先导性能及ACO/CPU基线覆盖
  diagnostic/E01/p01/              工作量、阶段和资源诊断
  historical/E02/p01/              历史协议及独立统计
  smoke/                          只说明验证范围，不发布科研加速比
  status/                         当前盘点与带日期的历史启动记录
```

每份科学报告的内部结构固定为 `README.md`、`tables/`、`figures/`、`provenance.json`。`tables`是可重建的CSV/JSON；`figures`同时保存PDF/SVG/PNG。大数组、checkpoint、profiler原文件、完整日志和原始外部导出不放进 `docs/results`。

若同一旧队列包含计时和profiling，原目录暂时不拆分，但汇总必须按每条记录的 `instrumented` 字段分开。规范报告不会整包复制旧summary后将其当作正式结果。

## 3. 名称与身份

- E00–E13沿用研究计划，不另造一套编号。每组产物登记主要实验及必要的关联实验。
- `p01`表示已登记的协议修订，不表示“重跑了一次”。科学预算、语义或计时边界发生不兼容变化才登记新协议。
- 同一设置重跑用 `a01`、`a02`，记录 `retry_of` 和原因；不覆盖旧输出。禁止 `new`、`latest`、`final2`、`test123` 等无法解释的名称。
- 性能运行示例：`tsp100-as-g001-cpu-numba-c16-b000-a01`。训练示例：`tsp500-as-cuda-generated-a5000-seed1001-a01`。文件名只包含主要识别轴；P/B/R/A/I等完整预算放入manifest，不能从文件名猜测。
- seed、block、重复任务和GP根种子分开记录。不能把100个程序、32个实例或重复的ZERO树当作100/32个独立训练重复。
- 输入包、共享缓存、源码、锁和日志不是实验结果，单独登记。

每个新运行至少写：登记ID、证据等级、实验编号、协议ID、运行ID、attempt、代码commit与source hash、输入/cohort/配置哈希、随机流与seed、计时边界、硬件/环境、预算、状态、失败/排除原因。不可获取的指标为null并注明原因。已有旧manifest不原地补写；其分类由登记表关联，原始字节和原哈希保持不变。

## 4. 结果生成和正式发布

报告读取明确登记的来源，不能递归扫描整个 `artifacts` 后把所有 `record.json` 合并。必须验证输入和结果哈希、实验身份及数据划分。去除重复attempt不能去除失败日志；用于统计的排除表要保留原因。

每份 `provenance.json`记录生成时间、报告脚本哈希、输入记录路径及SHA、筛选规则、记录数和输出文件SHA。路径迁移另外记录原路径→新路径；不修改历史manifest中的地址或哈希来掩盖迁移。

正式发布须同时具备：预先冻结协议、预设重复全部交代、语义检查、输入/结果身份核验、合法性检查、争用和失败处理、成对比较完整性、统计单位和置信区间说明。满足这些条件后新建正式报告；保留先导报告，不用“移动到formal”替代正式实验。

## 5. 当前迁移策略

首先迁移已结束的smoke、初始诊断、CPU/GPU冻结输入副本和旧bootstrap原始包。迁移逐文件计算SHA，改名后复核，写迁移日志。不删除实验数据，不覆盖目标，不改动文件内部的历史地址。

下列对象暂不迁移：仍在计算的训练与跨卡队列、训练启动日志、旧源码快照、共享ACO缓存和设备锁。控制器还在读写绝对路径；训练cohort仍被其他队列依赖。即使某个子实验完成，也不能只移动该子目录。所有这些例外在登记表中列明原因。

原A5000基线队列在74项完成、36项依赖等待且无测量worker运行时，已通过STOP_DISPATCH退出控制器，迁移到规范目录，随后用原commit恢复。文件逐一校验，旧顶层地址只保留指向新目录的兼容软链接。数据实际只存在一份。这与“只建一个指向旧目录的新快捷方式”不同；存储状态明确标为canonical_with_legacy_alias。旧文件内的绝对地址和哈希不改写。

尤其不能复制或替换锁文件inode，否则新旧worker会持有不同的锁。已有后台任务仍用原源码；不热更新或重启它们来整理目录。待所有相关写入者和消费者退出后，重新检查并单独执行迁移。

迁移只允许登记为 `move_inactive` 或 `move_idle_controller` 的明确目标。后者必须先确认控制器退出、测量worker为零，并显式保留兼容入口。`scripts/manage_artifacts.py inventory`只读盘点；`migrate --execute`才迁移。不对NFS上的活跃目录实施存在路径空窗的热迁移。

## 6. 后续执行纪律

1. 先在登记表登记问题、证据等级、协议、输入和输出位置。
2. 新的CPU测量和GPU诊断入口校验登记路径；随手写到artifacts顶层直接拒绝。
3. 每次独立attempt保留原始记录。报告只读已完成且符合自身筛选条件的记录。
4. 功能验证只写smoke，历史导入只写historical，插桩只写diagnostic。
5. 生成分类报告及来源manifest，再更新结果总索引。不能只发一张无法追溯的图。
6. 清理或压缩另行指定目标。目录管理本身不授权删除失败记录、旧baseline或checkpoint。
