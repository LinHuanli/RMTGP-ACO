# 异构 GPU 先导实验执行方案

日期：2026-10-10。状态：实现完成、五卡后台先导已启动，详见[运行记录](../results/hardware_pilot_status.md)。研究对象是同一 GP–ACO 工作负载在不同硬件上的执行效率。本文不预先认定某张卡更快，也不把硬件型号差异解释为某个单独硬件特性的因果效应。

## 1. 范围与固定量

本轮增加 RTX A5000、A40、L40S、L4 和 RTX PRO 5000 Blackwell 五类硬件。每类使用一台主机上的一张物理卡。现有六个 A5000、50 代先导训练继续使用原快照，不迁移、不改参。

主性能与短训练实验采用 AS。AS、同步 ACS、MMAS 均通过基础 E00 单元和闭环检查后，才进入性能流程。基础检查不代表已经完成研究计划中全部真实状态 E00 实验。

| 固定项目 | 设置 |
|---|---|
| 规模 | TSP100、TSP500；每张卡先完成 TSP100，再进入 TSP500 |
| GP population | 100；单棵转移树，节点≤31，深度≤5 |
| 主训练批次 | 每代32个独立实例；1个ACO重复 |
| ACO | 32只蚂蚁、500次迭代、候选表20、无局部搜索 |
| 数值 | FP32；保留逐节点保护；不启用 fast-math 或 FMA 收缩 |
| 随机 | 同一 Philox、实例标识和用途命名空间；不使用物理 GPU 编号派生搜索随机流 |
| 短训练 | 3代 × 3个根种子1001–1003 × 2个规模 × 5张卡，共30次 |
| 验证 | 固定128实例、3次ACO重复；每5代及最后一代；本轮仅第3代选优 |
| fitness 缓存 | 关闭；相同表达式仍执行完整逻辑任务 |
| 标准测试 | 封存。TSP100=1280、TSP500=128，保持原实例与顺序 |

本轮不新增50代训练，不做低精度实验，不改变宿主规则，不把多卡并行运行独立实验称为单次训练的多卡加速。

## 2. 统一输入和规范参考

`hardware_inputs.py` 在指定物理 A5000 所在主机生成一次下列数组，并记录 SHA256：FP32 坐标、距离、启发值、log启发值、候选表、完整排名、标签路径长度、实例 key，以及每个搜索随机流对应的初始信息素及上下界。后续各卡只读 mmap，不在不同 CPU 上重新计算这些输入。

各根种子的训练实例日程保持原协议：`SeedSequence([seed,n,1801])` 的无重复排列。前3代共96个实例。跨硬件相同 seed 使用相同日程与初始种群。不同规模的训练日程独立。

固定 ACO 对照为 ZERO 树。它由配置指定的 A5000、默认 lanes=8、active=3200 预生成，保存长度、路径、源码/数学/硬件身份及实际生成耗时。消费者缺失缓存时直接报错，不允许在另一张卡补写。参考库以 `READY.json` 原子提交；未提交或哈希不匹配的库不可使用。

这解决了异构实验中的“先写缓存者决定对照”问题。它不意味着不同 GPU 的浮点数学函数必然逐位相同。实验保存原始路径、长度和数组哈希，保留分析闭环轨迹差异的证据。

## 3. 执行计划筛选和留出测量

调优使用原 A5000 seed1001 训练保存的第1代真实100程序。留出使用 seed1002 的第1代100程序。程序来源、完整表达式和哈希均冻结；两个规模重放同一组程序，隔离规模变化。

每个 GPU × 规模按以下顺序执行：

1. active上限3200，筛选每蚂蚁4、8、16、32线程。每配置预热后完整测量一次。编译寄存器资源不足的方案记为不可行，不能减少蚂蚁数来使其可行。
2. 固定上述最快合法 lanes，比较 active上限为 `2×SM数`、`4×SM数`、3200。3200点复用第1步已测记录，不重复作为独立样本。
3. 以暖 `eval_wall_s` 选择。若相对默认配置的耗时下降不足3%，保留默认配置。该阈值是避免小波动驱动选择的先导规则，不是统计显著性阈值。
4. 将选定计划及时间写入 `selected_plan.json`。之后不使用 holdout 再调参。
5. 在独立 holdout 实例及程序上，以相同随机流进行5个配对 block。每个 block 随机化默认/选定配置的顺序。即使选定配置等于默认配置，也实际重复执行两个角色；不制造加速比恰为1的零方差数据。

各卡使用同一留出前32个独立实例；block改变ACO随机流，不改变实例身份。跨卡可按 block 配对。当前只有每型号一张物理卡，不能把5个block当作5张独立GPU。

## 4. 利用硬件差异的可检验假设

不先将 A40 的大显存、Ada 的较大缓存或 Blackwell 的新架构等同于本任务收益。先记录实际设备的SM数量、计算能力、L2容量、可见显存、寄存器/共享内存限制、ECC、功耗限制和CPU信息，再检验：

- 较少 active任务能否减少密集状态的工作集和显存流量，同时保留足够并行任务。
- 不同 lanes 是否改善候选并行性；是否被寄存器数量和最大 block 线程数限制。
- B从32增至128后，较大显存是否减少波次，以及额外驻留是否反而降低效率。
- L4 的绝对时间与整卡能耗是否呈现不同取舍。

容量探索使用同一100程序和128个不同的 holdout 实例，比较 active上限3200/12800，每点只测一次。显存不足时只分波次，始终完成12800个逻辑任务。记录请求上限、实际 active、波次数及采样显存峰值。此部分不用于重新选择已冻结的短训练计划，也不作为5-block统计结果。

## 5. 短训练与质量审计

各卡用各自选定计划进行3-seed短训练。进化和验证逻辑保持原协议。记录每代训练最优/中位 gap%、固定ACO gap%、二者差值、评估时间、整代时间、验证时间、编译时间，以及种群多样性。

每次训练由本卡验证选出一个冠军。后续在统一 A5000 执行器、统一128实例×3重复上重评该冠军。该审计不重选冠军、不回传适应度、不访问测试集。分别报告本卡验证值与共同执行器值，避免把不同卡的数学差异误归因于进化改进。

3代只适合观察吞吐、数值稳定性和早期进化现象。每个设置的3个GP根种子属于探索性证据，不能支持最终解质量优越性的正式结论。

## 6. 计时、能耗和统计边界

| 指标 | 边界 |
|---|---|
| 输入准备 | SHA审计、几何及规范参考生成单列，不计入暖评估 |
| 预热 | 同一程序/布局、I=1；CUDA源码不随I改变；编译、预热耗时单列 |
| 编译缓存 | 同时注明进程内缓存和可能的CuPy磁盘缓存；不声称获得真正冷编译时间 |
| device search | CUDA events的construct+update，不含全部主机步骤 |
| warm eval wall | 已准备输入到结果回传；包括初始化、上传、分配、搜索；不包括结果合法性校验与NPZ保存 |
| generation / training wall | 原训练协议的外层墙钟；包含实际新种群编译、验证和保存 |
| 分阶段诊断 | 独立插桩运行；不混入正式性能样本 |
| 能耗 | NVML整卡累计能量差，单位J；不支持则采样功率积分并注明实际覆盖区间 |
| 显存 | CUDA pool reserved和NVML采样整卡峰值分开；1秒采样不是严格瞬时峰值 |
| 争用 | 起止及运行中记录其他GPU进程；污染样本不进入干净性能配对 |

NVML温度、SM/显存时钟、功耗每秒采样；争用每15秒及测量边界检查。监测本身有少量开销；功耗积分和device search的时间边界不完全一致。不会调整ECC、功耗限制或锁频，不触碰其他用户进程。

硬件性能计数器未采集时，occupancy和实际DRAM带宽保持缺失。`nvidia-smi`的GPU利用率100%不能证明CUDA核心满载。

性能报告中位数、完整配对数、配对block bootstrap探索性95%区间及全部原始样本。单点调优和容量探索不带正式置信区间。质量保留3个seed各自的训练/验证结果，不把实例当作GP独立运行。跨卡速度同时给出默认布局和各卡选定布局，分开说明硬件与调优的影响。

## 7. 运行、产物与故障处理

```bash
source scripts/env.sh
python scripts/launch_hardware_pilot.py            # 只检查，不启动
python scripts/launch_hardware_pilot.py --execute  # 已提交快照 + 五卡 nohup
python scripts/report_hardware_pilot.py           # 可重复增量汇总
```

所有路径在本项目内：

```text
artifacts/hardware-pilot-v1/
  campaign.json
  inputs/tsp{100,500}/              # 共享只读几何、初始化、参考及SHA清单
  devices/<gpu>/
    job.json, hardware.json, E00.log
    worker.log, status.json, heartbeat.json, telemetry.jsonl
    tsp<n>/
      tuning/, selected_plan.json, holdout/
      training/seed-100{1,2,3}/
      diagnostics/, capacity/
  canonical_audit/tsp<n>/<gpu>/seed-<seed>/
  summary/                         # CSV、JSON、Markdown、PNG、PDF
artifacts/runtime/<git-commit>/     # 不可变代码快照
```

启动前同时检查UUID、进程、显存和利用率。工作进程再次检查，并使用与旧pilot共用的GPU互斥锁。已有目录拒绝覆盖；失败写入 `FAILED.json`，不静默降低科学规模或自动改设备。报告失败不销毁已完成的原始测量。A5000写入者失败时，等待该输入库的消费者退出并记录原因。

TSP500明显比TSP100昂贵，且本轮有完整配对、9代短训练和B128容量探索。后台正常运行不等于已经完成。应从状态、已提交记录和实际实测耗时更新进度，不能仅凭进程启动给出加速结论。
