# p02：局部搜索性能扩展与联合训练

日期：2026-10-10。用户已选择同时进行性能扩展和联合训练，并覆盖 AS、同步 ACS、MMAS。本文补充协议04、10，不改写已经运行的 p01。

## 1. 研究边界

问题是：加入局部搜索后，整代评价的成本如何变化？将局部搜索的候选计算移到 GPU 协作执行，能否在相同路径改进规则下缩短时间？GP 在固定局部搜索的环境中进化，是否仍优于同宿主、同局部搜索、同预算的 ZERO 规则？

本次不增加 LSGain、Origin 或其他终端。不改树深度、函数集、GP算子或残差形式。性能实验中的无局部搜索、2-opt、3-opt是三个不同算法负载；三者时间比不是同算法加速比。标量2-opt/协作2-opt及标量3-opt/协作3-opt才是等义执行器比较。

标准测试保持封存。50代联合训练每组3个独立根种子属于先导，不升级为10-seed确认性结果。

## 2. 局部搜索合同

每轮 ACO 顺序为：构造全部路径 → 改进全部32条路径 → 维护最好解 → 全局信息素更新。AS强化全部改进路径。ACS和MMAS按原宿主规则强化改进后的相应最好路径。ACS构造期间的同步局部更新不变。最近邻初始化、蒸发率、MMAS边界及重启不变。

| 项目 | 定义 |
|---|---|
| 距离 | 连续欧氏距离FP32；不是ACOTSP的整数TSPLIB距离 |
| 候选 | 静态最近20邻居，距离平局按城市编号 |
| 2-opt | 随机城市顺序；先后继切边、后前驱切边；按候选顺序取第一个有效下降；使用端点DLB |
| 3-opt | 先2-opt收敛；再扫描四种真正三边重连；接受后清空2-opt DLB，重新运行2-opt；循环至候选邻域无改进 |
| 三边候选 | 当前城市的近邻 × 当前后继的近邻；切边位置排序；排除相邻切边；按两层候选及pattern顺序扫描 |
| 三边DLB | 不使用，以免2-opt无改进被误当成3-opt无改进 |
| 随机顺序 | 每次迭代、实例、蚂蚁用Philox用途4作Fisher–Yates；程序之间共同随机数；扫描遍数之间重用排列 |
| 停止 | 无隐藏的移动数或扫描遍数上限；不因耗时长减少搜索 |
| 输出 | 改进路径及按城市位置升序FP32累加的长度；改进路径进入信息素更新 |

令移除边长的FP32和为 $R$，新增边长的FP32和为 $A$。只有满足

$$A-R < -\left[10^{-7}+8\epsilon_{32}(R+A)\right]$$

才接受移动。2-opt的和包含两项，3-opt的和按左结合包含三项。关闭fast-math及FMA。离线FP64仅用于功能审计，不反馈搜索。参考ACOTSP的候选表、first-improvement和DLB设计；不声称逐行复现ACOTSP的整数实现、较短片段反转或所有3-opt剪枝。

## 3. 并行执行

逻辑路径按 `(program, instance, ant)` 展平。路径为`uint16[tasks, ants, n+1]`。位置表为`int32[tasks*ants,n]`。城市排列不依赖程序，每轮仅生成`int32[batch*ants,n]`，各程序共享只读排列。DLB为`uint8`，重连临时路径为`uint16`。距离按实例共享。

标量参考每线程处理一条路径。协作版每warp处理一条路径。warp按候选序号分块计算gain，用最小有效序号归约保持first-improvement。被接受的移动使用临时缓冲协作复制，再更新位置表。3-opt只计算当前候选块，不物化整代所有三边组合。随机排列按实例/蚂蚁由一个线程生成；长度按升序保留单lane累加。每轮构造、LS、更新之间不传回CPU。

每路径工作区为约`7*n+32`字节，另有`4*batch*ants*n`字节共享排列。容量估算保守预留每路径`11*n+32`字节。显存不足时减少活跃任务、增加waves，不减少逻辑任务、蚂蚁或迭代。基础四项计数为2-opt移动、3-opt移动、逻辑候选检查和2-opt扫描遍数；逻辑检查不等于GPU实际投机计算的候选总数，也不是硬件指令数。

## 4. 有限实验清单

| 类别 | 设计 | 数量与证据等级 |
|---|---|---|
| E00资格 | 每个实际使用的A5000检查原无LS合同、CPU/Python/Numba及GPU两执行器、n=9/100/500固定路径及三宿主闭环 | smoke；先检查后派科学任务 |
| 执行器调优 | 3宿主×2规模×2LS；各5个同卡配对block，scalar/cooperative随机顺序 | 12任务，120评价；tuning |
| 完整预算短训练 | 12配置，各seed9001，P100/B32/A32/I500/K20，3代；最后一代做规定验证 | 12任务；smoke，不进入统计 |
| E09联合训练 | 12配置，各seed1001–1003，50代 | 36任务；pilot |
| E12冻结种群性能 | 2规模×3宿主×第1/25/50代×5block；每block五计划同卡随机顺序 | 90block，450评价；pilot |
| E01阶段诊断 | 12配置，第1代block0，选定执行器的插桩/无插桩配对 | 12任务；diagnostic |

五计划为none、2-opt scalar、2-opt cooperative、3-opt scalar、3-opt cooperative。三个宿主共享来自AS先导seed1002的真实性能cohort；这是跨宿主执行，不是三宿主各自进化的cohort。36次联合训练则由三个宿主分别进化。

tuning使用独立tuning实例前32个，以及命名空间`(7403, ls-tuning-programs, n)`生成的100棵完整独立初始树，不读取性能holdout选计划。每配置取5个干净配对block的墙钟中位数。默认cooperative；scalar至少快3%才切换。缺失、争用或输出不一致不能通过门禁。性能holdout不反向修改已选执行器。

## 5. 训练与缓存

科学规模仍为P100/B32/R1/A32/I500/K20/G50；节点≤31，深度≤5。验证每5代，128实例×3个ACO重复；候选为当代训练前5名及历史冠军。最终选择仅看验证。

每run训练前独立冻结50个训练场景和3个验证场景的ZERO+同LS对照。短训练为3+3场景。保存几何、候选、FP32标签长度、初始化、日程、初始种群、baseline路径与长度。缓存身份包含源码、LS参数及随机流。准备成本与训练墙钟分列，同时报告两者之和。不把准备阶段的时间从总成本中隐藏。

fitness仍为相对于同几何标签的gap%；同时逐代记录训练最好、种群中位数、ZERO对照与差值，验证只记录实际发生的验证点。不以训练batch最好值替代验证泛化。LS计数和编译时间进入代记录；阶段事件只用于独立诊断。

## 6. 调度与失败规则

每60秒扫描空闲A5000。UUID锁与启动复查和旧队列共用。代码提交后创建不可变快照，worker通过nohup运行。独立配置按“设备资格→调优→三代smoke→50代训练”解锁，无须等全部配置完成。

就绪任务按2个训练槽、1个测量槽交替派发；一类无就绪任务时借用。训练类优先TSP500。科学失败保留原attempt，不无限重跑；失败/争用门禁的后继明确标为`blocked_dependency`。启动前发现设备占用可换空卡。其他GPU型号不混入A5000时间统计。

E07原有两个受争用block独立登记修复：`as-tsp500-g001-b002`、`as-tsp100-g050-b002`。a01保留，补测从a02开始，沿用原科学源码、输入、种子和计划次序。启动前锁冲突会保留REJECTED并递增attempt编号，不增加科学样本。修复队列不改写正在运行的原队列。补测不是新统计重复。
