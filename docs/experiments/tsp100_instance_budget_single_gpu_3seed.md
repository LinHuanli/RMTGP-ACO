# TSP100 单卡训练实例预算实验结果

## 1. 实验目的

本实验研究每代训练实例数对运行时间和泛化质量的影响。比较的预算为
32、64 和 128。其余参数保持不变：

- ACO 变体为 ACS；
- 蚂蚁数为 32；
- ACO 迭代数为 500；
- GP population 为 100；
- GP 代数为 50；
- 每个预算使用 3 个 GP root seed，即 2001、2002 和 2003；
- 每个训练进程只使用一张 NVIDIA RTX PRO 5000 Blackwell；
- 后端为 `cuda_tiled_v2`；
- 数值 profile 为 `fp32_fast` 和 8 candidate lanes。

对相同的 GP seed 和 generation，32 个训练实例是 64 个训练实例的子集。
64 个训练实例是 128 个训练实例的子集。三个预算也共享 GP 初始种群、
ACO 随机种子和冻结 validation 数据。因此，预算之间可以进行配对比较。

最终测试只评测每个 run 的 `selected_candidate.pkl`。它不评测最后一代的
全部 population。测试将一个原始 ACS baseline 和九个最终候选打包为
10-program batch。测试使用两张 GPU 做确定性分片。

## 2. 完成状态和完整性检查

九次训练均正常结束。四个测试 partition 均正常结束。后台没有剩余训练
或测试进程。测试记录数如下。

| Partition | Instances | ACO seeds | GP candidates | 记录数 |
|---|---:|---:|---:|---:|
| TSP50 uniform | 1280 | 3 | 9 | 34560 |
| TSP100 uniform | 1280 | 3 | 9 | 34560 |
| TSP500 uniform | 128 | 3 | 9 | 3456 |
| TSP1000 uniform | 128 | 3 | 9 | 3456 |

四个文件共包含 76032 条候选记录。检查未发现重复主键、缺失值或非有限
gap。对于相同的 instance 和 ACO seed，九个候选使用完全相同的 baseline
结果。

## 3. 单卡训练时间

表中的数值为三个 GP seed 的均值和样本标准差。`50 代进化`包含每代训练
评测、固定 validation monitor、繁殖和 checkpoint。`端到端`还包含训练后
候选筛选、validation gate 和 CPU FP64 audit。baseline 已预先缓存，因此
不计入端到端训练时间。

| 每代实例数 | 每代时间 (s) | 50 代进化 (min) | 端到端 (min) | 评测吞吐 (M tours/s) |
|---:|---:|---:|---:|---:|
| 32 | 7.63 ± 1.48 | 6.36 ± 1.24 | 7.71 ± 1.24 | 6.44 ± 0.61 |
| 64 | 10.43 ± 2.68 | 8.69 ± 2.23 | 10.04 ± 2.26 | 7.57 ± 0.32 |
| 128 | 17.21 ± 2.56 | 14.34 ± 2.13 | 15.69 ± 2.15 | 9.36 ± 0.08 |

端到端单次运行范围分别为：

- 32 个实例：6.32--8.73 min；
- 64 个实例：7.83--12.35 min；
- 128 个实例：13.29--17.44 min。

相对 32 个实例，64 个实例的数据量增加为 2 倍，但端到端时间只增加
30.2%。128 个实例的数据量增加为 4 倍，但端到端时间增加为 2.03 倍。
评测吞吐从 6.44 M tours/s 增加到 9.36 M tours/s。128-instance batch
可以提供更多并行 task，因此 GPU 利用更充分。

不同 GP seed 的时间仍有明显差异。主要原因是语义去重后的待评测个体数
不同。每代平均唯一待评测个体数在不同 run 中约为 58--86。因此，墙钟
差异不能全部归因于 instance 数。

## 4. 最终测试结果

定义

\[
\Delta=\operatorname{gap}_{\mathrm{RMTGP}}
       -\operatorname{gap}_{\mathrm{baseline}}.
\]

因此，负的 \(\Delta\) 表示 RMTGP-ACS 更好。每个 GP candidate 先在同一
instance 上对 3 个 ACO seed 求均值。下表再对 3 个 GP seed 和所有测试
instance 求均值。

| 测试规模 | Baseline gap (%) | 32 gap / Δ (pp) | 64 gap / Δ (pp) | 128 gap / Δ (pp) |
|---|---:|---:|---:|---:|
| TSP50 | 0.7005 | 0.6544 / -0.0461 | **0.6501 / -0.0504** | 0.6757 / -0.0248 |
| TSP100 | 1.9358 | 1.6106 / -0.3252 | **1.5977 / -0.3381** | 1.6258 / -0.3100 |
| TSP500 | 16.0822 | 12.6558 / -3.4265 | 12.4316 / -3.6506 | **12.2874 / -3.7948** |
| TSP1000 | 21.6125 | 19.1227 / -2.4898 | 18.8222 / -2.7903 | **18.7391 / -2.8734** |

三个预算在四个测试规模上的平均 gap 均低于 baseline。进一步检查每个
GP seed 后，36 个“预算 × GP seed × 测试规模”组合的平均
\(\Delta\) 也全部为负。因此，在本次样本中，进化得到的最终候选稳定优于
原始 ACS baseline。

相对 baseline gap，三个预算的 gap 降幅如下。

| 测试规模 | 32 | 64 | 128 |
|---|---:|---:|---:|
| TSP50 | 6.59% | **7.20%** | 3.54% |
| TSP100 | 16.80% | **17.47%** | 16.01% |
| TSP500 | 21.31% | 22.70% | **23.60%** |
| TSP1000 | 11.52% | 12.91% | **13.29%** |

这里的“相对降幅”是对 gap 的相对变化。它不是 tour length 的相对变化。

## 5. 增加训练实例的边际效果

下表给出较大预算减去较小预算后的平均 gap 变化。负值表示较大预算更好。

| 测试规模 | 64 - 32 (pp) | 128 - 32 (pp) | 128 - 64 (pp) |
|---|---:|---:|---:|
| TSP50 | -0.0043 | +0.0213 | +0.0256 |
| TSP100 | -0.0129 | +0.0152 | +0.0281 |
| TSP500 | -0.2241 | -0.3684 | -0.1442 |
| TSP1000 | -0.3005 | -0.3836 | -0.0831 |

结果呈现出规模相关的趋势。

- 在训练分布 TSP100 上，64 个实例的点估计最好。128 个实例没有继续改善。
- 在 TSP500 和 TSP1000 上，128 个实例的点估计最好。
- 128 相对 64 的额外收益较小。TSP500 和 TSP1000 分别只改善
  0.1442 pp 和 0.0831 pp。
- 在 TSP50 和 TSP100 上，128 的点估计反而弱于 64。

但是，这些差异不能被解释为确定的训练预算效应。训练预算实验的独立重复
单位是 GP seed，而不是测试 instance。本实验只有 3 个 GP seed。以 GP
seed 为单位检查时，128 相对 32 只在 2/3 个 seed 上改善 TSP500 和
TSP1000。它只在 1/3 个 seed 上改善 TSP50 和 TSP100。所有预算对比的
方向都不是三个 seed 完全一致。因此，当前数据支持趋势描述，但不支持
“128 显著优于 64 或 32”的结论。

## 6. Validation 和 CPU FP64 audit

GPU validation selection 在 9 个 run 中通过 7 个。CPU FP64 final audit
在 9 个 run 中通过 6 个。每个预算均有 2/3 个 run 通过最终 gate。

未通过最终 gate 的 run 为：

- 32 instances，seed 2001；
- 64 instances，seed 2001；
- 128 instances，seed 2002。

其中，64-seed2001 和 128-seed2002 的 CPU mean delta 仍为负，但置信上界
超过 0.10 pp 非劣阈值。32-seed2001 在 GPU selection 上的 mean delta
为 -0.3515 pp，但 CPU FP64 audit 为 +0.1145 pp。该 run 表明离散 ACO
轨迹可能放大 FP32-fast 与 CPU FP64 的差异。

按照预先定义的部署规则，这三个 run 会部署 baseline fallback。但是，本次
训练预算研究的最终测试按照“只测试每个 run 的最佳最终候选”的要求，评测
的是九个 `selected_candidate.pkl`，而不是 fallback。论文中必须明确区分
“候选算法效果分析”和“通过安全门后的部署结果”。

## 7. 并行测试时间

| 测试规模 | 双卡墙钟时间 |
|---|---:|
| TSP50 | 23.55 s |
| TSP100 | 53.91 s |
| TSP500 | 238.29 s |
| TSP1000 | 1830.81 s |
| 合计 | 2146.56 s（35.78 min） |

TSP1000 占总测试时间的 85.3%。测试已经使用 program × instance 打包、
128-instance batch 和双 GPU LPT 分片。当前剩余瓶颈主要来自 TSP1000 的
\(O(n^2)\) 候选状态和 500 次 ACO 迭代，而不是 Python 逐个候选循环。

## 8. 当前结论

本轮实验可以支持以下结论。

1. 新 CUDA 后端已经把 50 代正式训练压缩到单卡约 8--16 min。
2. 更大的 instance batch 明显提高 GPU 吞吐。四倍训练数据只需要约两倍
   的端到端时间。
3. 本轮所有最终候选在四个测试规模上的平均结果都优于原始 ACS baseline。
4. 64 个实例具有最好的 TSP100 性能和更好的时间收益比。
5. 128 个实例在 TSP500 和 TSP1000 上具有最好的点估计，但相对 64 的
   边际收益很小。
6. 只有 3 个 GP seed。当前结果不能证明增加训练实例本身带来统计显著改善。

如果正式实验以 TSP100 性能和计算成本为主要目标，64 个实例是当前更合理
的默认值。如果跨规模泛化到 TSP500 和 TSP1000 是主要目标，可以保留
128 个实例，但应增加配对 GP seeds 后再判断其优势。
