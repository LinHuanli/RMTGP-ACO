# Terminal 数值稳定性与历史机制实验的分离执行

## 1. 目的与边界

原 FP32 方差公式在恒定或近恒定输入上会产生伪信号。本对照只改变 terminal
统计计算，不改变 ACO 更新、2-opt、残差系数、实例、共同随机流或已有冠军。
旧结果和原冻结队列保持不变。默认 `terminal_statistics=legacy`。

修正输入后部署旧冠军是数值环境干预，不是重新训练。不能预设其质量一定改善。
历史实现的行为归因仍可研究，但必须明确包含其数值行为，不能当成理想数学实现的归因。
本阶段只使用 `diagnosis_dev`，不查看确认集，不启动重新训练。

## 2. 三个对照

| 配置 | 标准化计算 | 保持不变的部分 |
|---|---|---|
| legacy | 历史 FP32 均值及二阶原点矩方差 | 全部历史算法语义 |
| centered_fp32 | 平移后两遍计算均值和中心化方差，FP32 | 搜索、GP 和信息素仍为 FP32 |
| centered_fp64 | 相同中心化算法，仅统计量和归一化用 FP64，结果转 FP32 | 搜索、GP 和信息素仍为 FP32 |

稳定模式覆盖 TR 的 RTau/REta、PH 的 EdgeTau/EdgeEta/SourceQuality。
先选一个输入作为平移基点，计算偏移量的均值和中心化平方差。
常量输入的偏移量严格为零。相近 tau 使用 `log1p((tau-anchor)/anchor)`；
差异较大时使用 log 差，避免相对差舍入到 -1。
稳定模式没有增大保护 epsilon、删 terminal、改变强类型或调整 residual 幅度。
Numba 尚未实现这个独立干预，显式拒绝非 legacy 模式，不能静默忽略。

## 3. 执行规模

1. 六组 A5000 编译及小样本检查：AS/MMAS × 三种模式，2 实例、25 轮，horizon 仍为 5000。
2. 每种允许型号分别检查六组：32 实例、100 轮、horizon 5000。
   验证记录开关不改变路径、chunk=7 与重排等价、预算与 GP 输出重算。
   稳定模式还必须通过全部 terminal 的独立 FP64 输入 oracle 和常量/近常量/大动态范围算子检查。
   legacy 必须与原冻结 CUDA 源码逐路径及 anytime 对齐。已知 oracle 偏差作为观测保留。
3. 配对质量对照：32 个 TSP500 × 5 个 ACO seeds × AS/MMAS × baseline/3 个冠军 × 3 种模式。
   32 ants、5000 轮、候选表与 LS 候选表均为 20、ACOTSP 2-opt。
   共 3840 个逻辑求解。以 8 实例为分块，共 40 个配对任务。
   同一任务的三种模式在同一 GPU 顺序执行，模式顺序提前随机化。
4. 原实现 R×F×H 开发集：32 实例 × 5 seeds × 8 条件 × baseline/3 冠军，5120 个逻辑求解。
   独立历史行为门禁需核对 P0 复现与精度报告；不借此解除旧数学正确性门禁。

三种 GPU 各自验收、各自放行，不等待所有型号同时空闲。
同实例块和 replicate 的条件固定显卡型号，设备 UUID 和驱动存档。
资源发现每 60 秒一次，启动前复核空闲，发现外部占用让卡；任务通过 nohup 执行。

## 4. 记录和统计

三种模式均使用 schema 3 的完整记录，每 25 轮固定采样，每 100 轮提交，
每 500 轮保存恢复检查点。不得以提速为由丢弃机制诊断字段。
保存逐实例 reference gap、anytime、最终 tour、来源、终端、GP 输出、最终 deposit 和 LS 记录。
配对表报告稳定模式减 legacy 的 gap 百分点，以及各自相对 baseline 的差值。
baseline 必须逐路径和 anytime 不受统计模式影响。

质量报告先在实例内平均 ACO seeds，再对实例进行配对统计。
三个固定冠军分列；不能把三位冠军、5000 轮或大量边观测当成独立实例。
开发集结论为探索性。确认性实验仍需冻结修订后的协议。
不同轨迹上的 raw/deposit 差异不是同状态因果效应；同状态效应需另用保存状态重算或分叉。

精度模式选择只依据正确性和独立预热计时，不依据 gap 谁更好。
完整审计耗时不冒充无审计部署时间。先保留三组，不在途中按质量删组。

## 5. 空间与恢复

新队列位于独立 `artifacts/numerical-*` 目录，源码和队列冻结，代码修改后另建 cohort。
共享盘任务启动最低剩余空间为 150 GiB；空间不足则等待并报告。
日志分块无损压缩，几何每任务只存一份，检查点只保留最近两个恢复副本。
已完成子组校验哈希后复用，未完成子组按原随机流恢复。
不能删除历史记录或把失败记录覆盖成成功。

## 6. 首轮小样本检查

`numerical-smoke-v1` 的六组 A5000 检查已完成。AS/MMAS 的中心化 FP32 和
统计量 FP64 均通过全部保存 terminal 的 FP64 oracle，未放宽 `2e-5` 容差。
legacy 与原冻结 CUDA 的路径和 anytime 一致，但输入 oracle 的已知偏差仍存在。
CPU 专项为 33 passed、10 GPU skipped；GPU 小样本检查由独立 nohup worker 实际执行。
这些仅是 2 实例、25 轮验收，尚不是 32 实例或 5000 轮质量结论。

P0 补充审阅：旧 MMAS 三分布、三 seeds 的逐实例 gap 复现误差约 `1.1e-14`；
AS 的平均收益现象复现，但少量个体轨迹分叉，不能声称逐路径一致，历史文件也未保存 tours。
300 轮 GPU 与 Numba FP64 的组件效应差异最高约 `0.067` gap 百分点，
超过预设 `0.01` 的实际意义阈值。该比较混合后端与 LS 约简差异，不是单一 terminal 干预。
因此只批准原实现行为的开发集分析，不批准数值无关的机制结论，也不放行确认集。
